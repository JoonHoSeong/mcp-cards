# Pinecone MCP Server

## Overview
| Field | Value |
|-------|-------|
| **Name** | Pinecone MCP Server |
| **Category** | Vector Database |
| **Official** | ⭐ Official (Pinecone) |
| **Source** | https://github.com/pinecone-io/pinecone-mcp |
| **Transport** | stdio |
| **Install** | `npx -y @pinecone-database/mcp` |

## Description
Official Pinecone MCP server for vector database operations. Enables AI agents to perform vector similarity searches, manage indexes, upsert and query embeddings, and build RAG knowledge bases. Provides full access to Pinecone's serverless vector database for semantic search, recommendations, and anomaly detection workflows.

## Key Tools
| Tool | Description |
|------|-------------|
| `list_indexes` | List all Pinecone indexes in the project |
| `describe_index` | Get detailed configuration of an index |
| `query_vectors` | Query vectors by ID or vector similarity |
| `upsert_vectors` | Insert or update vectors with metadata |
| `delete_vectors` | Delete vectors by ID or metadata filter |
| `search_docs` | High-level semantic document search |
| `create_index` | Create a new vector index with dimension and metric |
| `describe_index_stats` | Get index statistics including vector count and dimensions |

## Configuration
```json
{
  "mcpServers": {
    "pinecone": {
      "command": "npx",
      "args": ["-y", "@pinecone-database/mcp"],
      "env": {
        "PINECONE_API_KEY": "your-pinecone-api-key"
      }
    }
  }
}
```

## Use Cases
1. Vector similarity search — find semantically similar documents or images
2. RAG knowledge base management — index, update, and query knowledge bases
3. Semantic search — natural language queries over unstructured data
4. Recommendation systems — find similar items based on embedding vectors
5. Anomaly detection — identify outliers in vector space

## Prerequisites
- Pinecone API key from the Pinecone console
- At least one index created (or use `create_index` tool)
- Node.js 18+ for npx installation
- Understanding of embedding dimensions matching your model output

## Security Notes
- Use separate API keys per environment (dev/staging/prod)
- Leverage namespace isolation to separate tenants within an index
- API keys provide full index access — scope to specific projects
- No built-in row-level security — implement filtering at application layer
- Monitor usage to prevent unexpected costs on serverless indexes
